ReelBinder supports readable screenplay interchange alongside structured Project snapshots and media archives. Use the application's serializers for a complete export. The internal interchange file names below are historical format identifiers and remain stable for compatibility.

## Three complementary parts

- **Markdown interchange** (`script.slate.md`) carries screenplay text and readable coverage definitions.
- **JSONL production records** carry structured marks, catalog data, discussions and other linked context.
- **A Project snapshot** preserves the editable state needed for a faithful round trip.

A portable `.slate.zip` pack can contain those documents and verified media. A text export alone is not a substitute for the complete pack. Current ReelBinder exports use the `.reelbinder.zip` archive; `.slate.zip` packs remain fully supported for import.

## Preserve identities and ranges

Script element IDs, setup IDs, catalog IDs, source ranges and timeline ranges have different meanings. Keep stable identifiers when editing existing material. A coverage span does not specify where that shot appears in the final edit.

Text marks should refer to an existing element and its exact current text. Character offsets must match that element's text; a guessed offset can anchor a note to the wrong words.

## Use complete records

Do not treat arbitrary partial JSONL rows as safe patches. Import and merge rules can distinguish missing fields, explicit empty values and inheritance. The source repository's format contract documents those cases and the supported record types.

## Verify the full round trip

A successful ZIP decode is only one step. Check the loaded Project, linked edits, media playback and persistence after import. Media bytes should match their declared hashes, and historical provenance should remain intact.
